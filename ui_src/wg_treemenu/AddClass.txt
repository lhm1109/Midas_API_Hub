//
//  추가된 Class Header File을 wg_treemenuAll.h에 include시킨다. 
//  include 위치와 상세한 내용을 해당Dll의 wg_treemenuAll.h 을 참조한다. 
//  
//  
//  DLL에서 다른 DLL을 참조 할때는 아래 예와 같이 해당 
//  DLL의  Interface Header File을 
//  wg_treemenuAll.h File과 stdafx.h File에 Include 한다.
//  Include 위치는 해당 파일을 참조할 것 .  
//  
//  #if !defined(__WG_BASEALL_H__)
//  	#include "..\wg_base\wg_baseall.h"
//  #endif
//
//  DLL간 Cross Reference가 가능할까? Extention DLL의 여러가지 특징에서 가능성이 
//  보인다. 단 Project Dependency 는 설정 할 수 없다. Project Dependency는 Project간 
//  주종 관계를 설정하는 것이므로 Cross Reference 상황에서는 사용할 수 없다. 
//  Cross Reference는 Module 결합도에 따라 가능 또는 불가능 할 수 있다. 
//  표면적으로는 Cross Reference이나 Module간 결합에서는 주종관계가 설정되어야 
//  한다. 실제로 완전한 Cross Reference는 동일 class또는 동일 Module에서만 
//  이루어 질 수 있다

_/                               Resource symbol 관련 처리 사항

//  
//  Dll 사용시 발생할 수 있는 Resource Symbol간 충돌 문제를 해결하기 위한 방안으로 
//  각 Dll에서 사용하는 Resource Symbol Name 과 Resource Symbol 값을 다르게 한다. 
//  Symbol Name에는 Prefix를 적용하고 Resource Symbol 값에는 Dll 별로 범위를 
//  지정한다. App Wizard에서 Resurce Symbol 값의 시작 값을 별도로 지정해 주지만 
//  때로는 이 시작값에 문제가 있을수 있다.  App Wizard로 Template 생성후 반드시 
//  확인해 볼것 . 다른 Module 의 Symbol값과 중복 되지 않도록 할 것. 
_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/
//  wg_treemenures.h 에서 _APS_NEXT_COMMAND_VALUE는 Menu Command의 Resource 
//  Symbol의 시작값이다. 이값은 Application Wizard에서 자동으로 지정해 줄수 없으므로 
//  모듈별 Resource ID 시작값을 작업자가 직접 지정해 주어야 한다. 
//  wg_treemenures.h 의 #define _APS_NEXT_COMMAND_VALUE   항목 값 변경       
_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/_/
//  현재 UI 관련 Library 로 Objectve Tool Kit과 Objective Grid를 사용하고 있는데 
//  이러한 Library들과의 충돌을 피하기 위한 조치로 Library에서 사용되고 있는 Resource 
//  Symbol 값 과 중복되지 않게 해야 한다. 
//  현재 OT, OG Library 에서 사용하는 Resource Symbol 값의 시작 값은 0x4E20이다 .
//  따라서 작업중인 Module의 Resource Symbol 값은 0x4E1F를 넘지 않아야 한다. 
//  이러한 제한에 적용되지 않는 Resource 는 Dialog Template 내에서 사용되는 Local Symbol
//  들이다 . Bitmap , Menu, Dialog Template.. 들은 Symbol 값의 중복을 허용하지 않는다. 

/////	Resource Symbol 값에 대한 관리는 Project 전체에 걸쳐 관리되어야 한다.

//
//  View/Resource Includes 의 Read Only Symbol Directives 항목에 참조하고자 하는 Resource
//  Header File 을 포함시킨다.  Path는 Main Project의 Root Directory 기준의 상대 위치 지정 
//  형식으로 설정한다. (ex  ..\wg_main\wg_mainres.h)
//
//  Class Wizard에서 참조 된 Resource Symbol을 Browse하기 위해 참조될 Rosourec를 Copy 한다 
//  Resource Header File이 Include 되었으므로 Symbol 값의 충돌은 발생하지 않는다. 
//
//  Copy 된 Resource 는 참조가 끝난후 삭제한다.  즉 다른 Module의 Resource이므로 필요할때마다 
//  임시적으로 Copy 해서 Symbol을 참조한다 .
//  ==> Resource Copy 시 참조 하고자 하는 Module의 Resource Header File을 Include 가 선행되지  
//  않으면 Resource Symbol간 충돌이 발생할 수 있다. 
// 
//  전술한 내용은 Extention DLL의 경우일 때만 적용된다. 
//  Extention DLL 은 별도의 Application Instance를 생성하지 않기 때문에 이러한 Trick이 가능하다.
